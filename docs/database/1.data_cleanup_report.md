# OBE 平台数据库数据清洗报告

> **生成日期**: 2026-06-23  
> **数据源**: `sql/obe_platform.sql`  
> **数据库**: obe_platform (MySQL 8.0)  
> **目的**: 梳理当前数据库中的测试/演示数据，为正式上线提供数据清洗方案

---

## 一、总体分析

当前 SQL 脚本共包含 **26 张表**的数据插入语句，数据总量约 **700+ 条记录**。根据数据性质可分为三类：

| 类别 | 表数量 | 说明 |
|------|--------|------|
| 配置/基础数据 | 9 | 系统运行必需的结构性数据，**需保留** |
| 测试/演示数据 | 14 | 开发测试期间产生的模拟数据，**需清除** |
| 运行时计算数据 | 3 | 基于测试成绩自动计算的结果数据，**需清除** |

**核心判断依据**：所有用户密码均为同一 BCrypt 哈希值、存在明显占位描述（如 "123"、"12312"）、大量规律性生成的学生和成绩数据。

- 考核点级成绩（question_id=NULL）：每个学生每个考核点一条记录，共 ~30 条
- 题目级成绩（question_id!=NULL）：每个学生每个考核点的每个题目一条记录，共 ~384 条

这两类数据同时存在，说明系统经过了"先导入考核点成绩，再录入题目级成绩"的完整测试流程。

**处理方案**: **全部清除**。学生成绩是核心业务数据，正式使用时必须从真实成绩单导入。

### 3.3 上线部署建议

1. **创建独立的生产初始化脚本**  
   从当前 SQL 脚本中分离出纯 DDL（建表语句）和必需的种子数据，形成 `sql/obe_platform_prod.sql`。

2. **用户密码安全**  
   当前所有用户使用相同 BCrypt 哈希（疑似 `123456`），正式上线后必须为每位用户设置独立强密码，建议集成学校的统一认证系统（LDAP/OAuth）。

3. **保留数据的使用**  
   如需保留 `grad_requirement` 和 `indicator` 作为模板数据，建议：
   - 补全缺失的指标点（当前仅覆盖 3 个毕业要求的 7 个指标点）
   - 将 `sys_major` 更新为实际专业后再建立外键关联

4. **AUTO_INCREMENT 重置**  
   清除数据后建议执行 `ALTER TABLE ... AUTO_INCREMENT = 1` 重置所有表的自增计数器，避免 ID 跳号。

5. **数据库备份**  
   在执行任何清除操作前，务必备份当前数据库：
   ```bash
   mysqldump -u root -p obe_platform > obe_platform_backup_20260623.sql
   ```
