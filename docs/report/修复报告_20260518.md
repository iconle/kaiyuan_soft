# 修复报告：登录异常排查

> 时间：2026-05-18
> 问题：使用 admin 账号登录时后端报错 `Unsupported character encoding 'utf8mb4'`

---

## 问题一：JDBC 连接字符集配置错误

### 现象

后端启动或连接 MySQL 时抛出异常：

```
java.io.UnsupportedEncodingException: utf8mb4
```

### 根因

`application-dev.yml` 中 JDBC URL 配置为：

```
characterEncoding=utf8mb4
```

MySQL Connector/J 驱动使用 **Java charset 名称**，而 Java 不识别 `utf8mb4` 这个名称。MySQL 8.0+ 驱动默认已使用 utf8mb4，无需在 URL 中显式指定字符编码。

### 修复

**文件：** `backend/src/main/resources/application-dev.yml`

移除 URL 中的 `characterEncoding=utf8mb4` 参数：

```
# 修复前
jdbc:mysql://localhost:3306/obe_platform?...&characterEncoding=utf8mb4

# 修复后
jdbc:mysql://localhost:3306/obe_platform?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Shanghai
```

---

## 问题二：init.sql 中 INSERT 语句顺序错误

### 现象

重新执行 `init.sql` 初始化脚本时，预置管理员账号插入失败。

### 根因

`INSERT IGNORE INTO sys_user`（预置管理员）位于 `CREATE TABLE sys_user` **之前**，表尚未创建就尝试插入数据。

```sql
-- 错误顺序（修复前）
INSERT IGNORE INTO sys_role ...;           -- 第 57 行
INSERT IGNORE INTO sys_user ...;           -- 第 65 行 ← 此时 sys_user 表不存在
CREATE TABLE IF NOT EXISTS sys_user (...); -- 第 71 行 ← 表建在这里
```

### 修复

**文件：** `docs/database/init.sql`

将管理员 INSERT 语句移至 `CREATE TABLE sys_user` 之后：

```sql
-- 正确顺序（修复后）
INSERT IGNORE INTO sys_role ...;
CREATE TABLE IF NOT EXISTS sys_user (...);
INSERT IGNORE INTO sys_user ...;           -- 表已存在，插入成功
```

---

## 验证步骤

1. 重新执行数据库脚本：`mysql -u root -p < docs/database/init.sql`
2. 重启后端：`cd backend && mvn spring-boot:run`
3. 前端登录：`admin / admin123`
