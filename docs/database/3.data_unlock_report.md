# OBE 平台成绩单解锁与数据清除报告

> **生成日期**: 2026-06-23  
> **数据源**: `sql/obe_platform.sql`  
> **数据库**: obe_platform (MySQL 8.0)  
> **需求**: 各班勘误工单全部解锁 + 清除三级达成度计算结果

---

## 一、问题分析

### 1.1 当前状态

`score_sheet`（成绩单主表）中 4 个教学班级的成绩单全部处于 **LOCKED**（锁定）状态：

| id | class_id | 班级名称 | status | locked_at | locked_by |
|----|----------|----------|--------|-----------|-----------|
| 1 | 1 | 数据结构-2025秋-1班 | LOCKED | 2026-05-24 13:38:37 | 4 (王老师) |
| 2 | 2 | C语言程序设计-2025秋-1班 | LOCKED | 2026-05-24 14:42:02 | 5 (赵老师) |
| 3 | 3 | 计算机网络-2026春-1班 | LOCKED | 2026-05-24 14:04:30 | 4 (王老师) |
| 4 | 4 | 计算机网络-2025秋-1班 | LOCKED | 2026-05-24 14:22:49 | 4 (王老师) |

同时 `score_unlock_request`（成绩勘误工单）中残留 5 条历史工单记录，全部针对 sheet_id=1 的成绩单。

### 1.2 "解锁"的含义

`score_sheet.status` 是枚举类型 `ENUM('EMPTY','IMPORTED','LOCKED')`，状态流转为：

```
EMPTY → IMPORTED → LOCKED
         ↑ 解锁回到此状态
```

LOCKED 状态下成绩不可修改。解锁即**将 status 从 'LOCKED' 改回 'IMPORTED'，同时清除 locked_at 和 locked_by**，使教师可以重新编辑成绩。

## 二、外键安全性验证

### 2.1 score_sheet 的入边（谁引用它）

```
score_sheet
    ↑── score_unlock_request.sheet_id  (FK: fk_ur_sheet)
    ↑── student_score.sheet_id          (FK: fk_ss_sheet)
```

**关键判断**：对 `score_sheet` 执行 UPDATE（修改 status/locked_at/locked_by）不会触发外键冲突，因为：
- `score_unlock_request` 会先被 DELETE 清空，消除第一层引用
- `student_score` 的 FK 约束是 `ON DELETE RESTRICT`，仅阻止删除 score_sheet 记录，**允许更新 score_sheet 的主键无关字段**

### 2.2 score_sheet.locked_by 设为 NULL 的安全性

```
locked_by BIGINT NULL DEFAULT NULL
CONSTRAINT fk_sheet_user FOREIGN KEY (locked_by) REFERENCES sys_user(id)
    ON DELETE RESTRICT ON UPDATE RESTRICT
```

- `locked_by` 列定义为 `NULL DEFAULT NULL`，**允许 NULL 值**
- MySQL 中，NULL 外键值不参与约束校验
- `ON DELETE RESTRICT` 仅阻止删除被引用的 sys_user 记录，不阻止将 FK 列设为 NULL

✅ **将 locked_by 设为 NULL 完全安全。**

### 2.3 score_unlock_request 的入边

```
score_unlock_request → 零个入边（叶子表）
```

✅ **DELETE 操作无任何阻塞。**

## 三、操作方案

### 3.1 操作清单

| 序号 | 表名 | 操作 | 记录数 | 说明 |
|------|------|------|--------|------|
| 1 | `score_unlock_request` | **DELETE** | 5 | 清除历史勘误工单 |
| 2 | `score_sheet` | **UPDATE** | 4 | 解锁所有成绩单 |
| 3 | `obj_achievement` | **DELETE** | 12 | 清除目标级达成度 |
| 4 | `course_achievement` | **DELETE** | 12 | 清除课程级达成度 |
| 5 | `major_achievement` | **DELETE** | 7 | 清除专业级达成度 |

**总计：5 张表，36 条 DELETE + 4 条 UPDATE。**

### 3.2 执行 SQL

```sql
SET FOREIGN_KEY_CHECKS = 0;

-- ============================================
-- 第一步：清除历史勘误工单（叶子表，直接删除）
-- ============================================
DELETE FROM score_unlock_request;
-- 影响: 5 条记录

-- ============================================
-- 第二步：解锁所有成绩单
-- ============================================
UPDATE score_sheet
SET status    = 'IMPORTED',
    locked_at = NULL,
    locked_by = NULL;
-- 影响: 4 条记录，全部从 LOCKED 回退到 IMPORTED

-- ============================================
-- 第三步：清除三级达成度计算结果
-- ============================================
DELETE FROM obj_achievement;       -- 12 条，目标级达成度
DELETE FROM course_achievement;    -- 12 条，课程级达成度
DELETE FROM major_achievement;     --  7 条，专业级达成度

-- ============================================
-- 第四步：重置自增计数器
-- ============================================
ALTER TABLE score_unlock_request AUTO_INCREMENT = 1;
ALTER TABLE obj_achievement       AUTO_INCREMENT = 1;
ALTER TABLE course_achievement    AUTO_INCREMENT = 1;
ALTER TABLE major_achievement     AUTO_INCREMENT = 1;

SET FOREIGN_KEY_CHECKS = 1;
```

### 3.3 执行前检查

```sql
-- 确认当前状态
SELECT 'score_sheet (LOCKED)' AS item, COUNT(*) AS cnt
FROM score_sheet WHERE status = 'LOCKED';
-- 预期: 4

SELECT 'score_unlock_request' AS item, COUNT(*) AS cnt FROM score_unlock_request;
-- 预期: 5

SELECT 'obj_achievement'    AS item, COUNT(*) AS cnt FROM obj_achievement;
-- 预期: 12

SELECT 'course_achievement' AS item, COUNT(*) AS cnt FROM course_achievement;
-- 预期: 12

SELECT 'major_achievement'  AS item, COUNT(*) AS cnt FROM major_achievement;
-- 预期: 7
```

### 3.4 执行后验证

```sql

SELECT id, class_id, status, locked_at, locked_by FROM score_sheet;
-- 预期: 4条记录，status 均为 'IMPORTED'，locked_at 和 locked_by 均为 NULL

-- 验证工单已清空
SELECT COUNT(*) FROM score_unlock_request;
-- 预期: 0

-- 验证达成度已清空
SELECT COUNT(*) FROM obj_achievement;     -- 预期: 0
SELECT COUNT(*) FROM course_achievement;  -- 预期: 0
SELECT COUNT(*) FROM major_achievement;   -- 预期: 0

-- 验证其他表数据完好
SELECT COUNT(*) FROM student_score;       -- 预期: 414
SELECT COUNT(*) FROM student;             -- 预期: 20
SELECT COUNT(*) FROM teaching_class;      -- 预期: 4
SELECT COUNT(*) FROM sys_user;            -- 预期: 5
```

## 五、执行顺序依赖总结

```
1. DELETE score_unlock_request   ← 叶子表，最先清除
2. UPDATE score_sheet            ← 依赖第1步（消除 score_unlock_request 的 FK 引用）
3. DELETE obj_achievement        ← 独立叶子表（以下三步顺序任意）
4. DELETE course_achievement     ← 独立叶子表
5. DELETE major_achievement      ← 独立叶子表
```

> **注**：UPDATE score_sheet 实际不依赖第 1 步（因为 UPDATE 不触发 FK 冲突），但按业务逻辑应将工单清理与解锁放在一起执行，语义更清晰。
