# 修复报告：非 admin 账号登录后无法跳转

> 时间：2026-05-18
> 问题：使用非 admin 账号登录，提示登录成功但停留在登录页，不跳转到对应页面

---

![image-20260518230229790](C:\Users\qzb\AppData\Roaming\Typora\typora-user-images\image-20260518230229790.png)

## 根因分析

登录成功后，`LoginView.vue` 固定执行 `router.push('/')`。而路由配置中 `/` 的 redirect 硬编码为 `/admin/users`。路由守卫检测到非 ADMIN 角色与 `meta.roles: ['ADMIN']` 不匹配，将用户重定向回 `/login`。

**调用链：**
```
login() → 成功 → push('/') → redirect '/admin/users'
  → 守卫: roleCode=TEACHER, meta.roles=['ADMIN'], 不匹配
  → push('/login') → 回到登录页
```

---

## 修复内容

### 1. LoginView.vue — 按角色跳转首页

**文件：** `frontend/src/views/login/LoginView.vue`

新增 `getHomeRoute(roleCode)` 函数，登录成功后根据角色跳转到对应首页：

| 角色 | 登录后跳转 |
|------|-----------|
| ADMIN | `/admin/users` |
| ACADEMIC | `/academic/courses` |
| DIRECTOR | `/director/grad-req` |
| TEACHER | `/teacher/1/objectives` |

### 2. Router index.js — 消除硬编码 redirect

**文件：** `frontend/src/router/index.js`

三处修改：

1. **移除** 根路由 `/` 的 `redirect: '/admin/users'` 硬编码
2. **新增** `getHomePath(roleCode)` 函数（路由级别），用于守卫中按角色计算首页
3. **修改** 路由守卫逻辑：
   - 访问 `/` 时按角色动态跳转首页
   - 角色不匹配时跳转到该角色首页（而非 `/login`）
   - 已登录用户访问 `/login` 时自动跳转到对应首页
