## 二、需求背景

### 1. 现状问题

在「毕业要求管理」页面中，专业负责人只能在每个毕业要求下**逐个新增指标点**。当一所专业的毕业要求指标点数量较多（常见十余条甚至更多）时，逐条手工填写编号与描述非常繁琐、效率低，且易出错。

### 2. 需求目标

- 新增「指标点导入」按钮，支持一次性批量导入指标点。
- 新增「下载模板」功能，提供标准填写模板。
- **导入模板的格式必须与专业负责人使用的导入模板保持一致**，否则系统应报错提示。
- **系统报错应明确指出问题所在以及用户需要修改的地方**。

## 三、功能设计

### 1. 模板格式

模板为一个 `.xlsx` 工作簿，包含两个 sheet：

**Sheet 1：指标点导入**（数据 sheet）

| 毕业要求编号 | 毕业要求标题 | 指标点编号 | 指标点描述             |
| ------------ | ------------ | ---------- | ---------------------- |
| 3            | 工程知识     | 3-1        | 能够将数学…           |
| 3            | （可留空）   | 3-2        | 能够针对复杂工程问题… |

- 表头（第一行）的**列名与顺序固定**，是导入时的强校验依据。
- 下载时会**预填当前专业下已存在的毕业要求**（编号 + 标题）作为行级提示，指标点两列留空。
- 首行冻结，方便长列表滚动。

**Sheet 2：填写说明**

列出 6 条填写规则（表头不可改、毕业要求编号须为已存在值、指标点编号/描述必填、空白行自动跳过等）。

### 2. 导入校验规则

| 校验项               | 规则                                      | 失败提示示例                                                      |
| -------------------- | ----------------------------------------- | ----------------------------------------------------------------- |
| 文件格式             | 必须为`.xlsx`                           | 仅支持 .xlsx 格式文件，请点击「下载模板」获取正确模板             |
| 表头一致性           | 首行必须与模板表头完全一致（列名 + 顺序） | 期望表头：…；实际表头：…                                        |
| 毕业要求前置         | 当前专业必须已存在毕业要求                | 当前专业尚未创建任何毕业要求，请先新增毕业要求后再导入            |
| 毕业要求编号         | 非空、整数、必须在当前专业存在            | 第3行：「毕业要求编号 9」在当前专业不存在（有效编号：1、2、3、4） |
| 指标点编号           | 非空                                      | 第5行：「指标点编号」不能为空                                     |
| 指标点描述           | 非空                                      | 第7行：「指标点描述」不能为空                                     |
| 指标点查重（库内）   | 不与已存在指标点重复（按归一化编号）      | 指标点编号「3-1」已存在，请勿重复导入                             |
| 指标点查重（文件内） | 本文件内不重复                            | 指标点编号「3-1」在本文件中重复出现                               |
| 空白行               | 完全空白的行自动跳过                      | —                                                                |

### 3. 错误反馈策略

- **收集全部行级错误一次性返回**（而非遇错即停），用户可一次性对照修正，减少反复试错。
- 每条错误包含：**Excel 显示行号 + 字段名 + 实际值 + 正确取值**，明确告诉用户「哪一行、哪个字段、出了什么问题、应改成什么」。
- 错误以多行文本返回，前端在弹窗中换行展示。

### 4. 设计取舍

- 导入**按当前选中专业**进行，指标点挂到该专业**已存在**的毕业要求下（按「毕业要求编号」匹配）。
- 本功能仅批量新增指标点，**不创建新的毕业要求**（毕业要求仍走原有逐条新增）。
- 涉及权限：沿用 `GradReqController` 的类级 `@PreAuthorize("hasRole('DIRECTOR') or hasRole('ACADEMIC')")`，与现有指标点接口一致。

## 五、接口说明

### 1. 下载导入模板

```
GET /api/grad-req/indicator-template?majorId={majorId}
权限：DIRECTOR / ACADEMIC
返回：application/octet-stream，文件名「指标点导入模板.xlsx」
```

### 2. 上传导入指标点

```
POST /api/grad-req/indicators/import?majorId={majorId}
Content-Type: multipart/form-data
参数：file（.xlsx 文件）
权限：DIRECTOR / ACADEMIC
返回：Result<Integer>，data 为成功导入的指标点数量
```

- 校验失败时返回 `code=500`、`message` 为逐条错误（换行分隔）。
- 校验通过且全部插入成功后返回 `code=200`、`data=N`。

## 六、关键实现说明

### 1. 后端 IndicatorImportService

- `generateTemplate(majorId)`：使用 Apache POI（`XSSFWorkbook`）手动构建工作簿，复用与「成绩录入模板」一致的样式风格；预填当前专业毕业要求作为填写提示。
- `importIndicators(majorId, file)`：
  - 先查询当前专业毕业要求，构建 `reqNo → gradReqId` 映射；若为空直接报错。
  - 查询已存在指标点构建查重集合（`gradReqId + 归一化编号`）。
  - 校验表头 → 逐行解析收集错误 → 无错则批量插入。
  - 全程 `@Transactional`，抛 `BizException` 由 `GlobalExceptionHandler` 统一转 JSON。

### 2. 前端

- `GradReqManage.vue` 头部新增「下载模板」「导入指标点」按钮，未选专业时禁用。
- 导入弹窗使用 `el-upload`（`:http-request` 自定义上传，`:before-upload` 校验扩展名）。
- 下载走 blob，并对「后端业务异常以 HTTP 200 + JSON 返回」的情况做判别，避免把错误 JSON 当成 xlsx 下载。
- 导入失败时，`request.js` 通过 `skipErrorMessage:true` 跳过全局 toast，由组件以 `ElMessageBox` 多行展示后端逐条错误（对内容做 HTML 转义后换行渲染，防注入）。

### 3. request.js 改动（向后兼容）

新增可选配置项 `skipErrorMessage`：调用方传 `true` 时，响应拦截器跳过全局 `ElMessage.error`，交由调用方自行处理错误展示。**默认行为不变**，不影响现有接口。

## 九、部署说明

### 后端

1. 切到 `lwp_99` 分支。
2. JDK 17 + Maven 构建：`mvn clean package -DskipTests`。
3. 用生成的 `obe-platform-1.0.0.jar` 替换部署目录中的旧 jar。
4. 重启后端服务。

### 前端

1. `cd frontend && npm run build`，产出 `dist/`。
2. 将 `dist/` 部署到 Nginx 静态目录（或按现有部署方式替换）。
3. 无需额外改 Nginx 配置（接口路径仍在 `/api/grad-req/**` 下）。
