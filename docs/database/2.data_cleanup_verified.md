## 二、外键依赖分析

### 2.1 外键关系回顾

四张目标表的外键约束均为**对外引用**（它们指向其他表），没有任何一张被其他表引用：

```
┌─────────────────────────┐
│  score_unlock_request   │
│  FK → score_sheet       │  (fk_ur_sheet)
│  FK → sys_user          │  (fk_ur_requester)
│  FK → sys_user          │  (fk_ur_reviewer)
└─────────────────────────┘
     ↑ 零个入边（无其他表引用此表）

┌─────────────────────────┐
│  obj_achievement        │
│  FK → teaching_class    │  (fk_oa_class)
│  FK → course_objective  │  (fk_oa_objective)
└─────────────────────────┘
     ↑ 零个入边（无其他表引用此表）

┌─────────────────────────┐
│  course_achievement     │
│  FK → teaching_class    │  (fk_ca_class)
│  FK → indicator         │  (fk_ca_indicator)
└─────────────────────────┘
     ↑ 零个入边（无其他表引用此表）

┌─────────────────────────┐
│  major_achievement      │
│  FK → sys_major         │  (fk_ma_major)
│  FK → indicator         │  (fk_ma_indicator)
│  FK → sys_dict_semester │  (fk_ma_semester)
│  FK → sys_user          │  (fk_ma_user)
└─────────────────────────┘
     ↑ 零个入边（无其他表引用此表）
```

### 2.2 验证方法

对 `sql/obe_platform.sql` 全量搜索 `REFERENCES` 约束，确认无任何表的外键指向这四张表：

```sql
-- 搜索结果：0 条匹配
REFERENCES `score_unlock_request`
REFERENCES `obj_achievement`
REFERENCES `course_achievement`
REFERENCES `major_achievement`
```

### 2.3 结论：完全可行

四张目标表全部是**依赖图的叶子节点**，且所有外键约束均使用 `ON DELETE RESTRICT`。`RESTRICT` 仅阻止删除被引用的父表记录，对于删除叶子表本身的记录没有任何影响。

因此，删除这四张表的数据**不会违反任何外键约束，不会影响其他任何表的数据完整性**。

## 四、执行方案

### 4.1 删除 SQL（推荐）

由于四张表之间无相互依赖，删除顺序任意：

```sql

-- 1. 清除成绩勘误工单
DELETE FROM score_unlock_request;

-- 2. 清除三级达成度计算结果（由底层向上）
DELETE FROM obj_achievement;       -- 第一级：目标级达成度
DELETE FROM course_achievement;    -- 第二级：课程级达成度
DELETE FROM major_achievement;     -- 第三级：专业级达成度

-- 3. 重置自增计数器
ALTER TABLE score_unlock_request AUTO_INCREMENT = 1;
ALTER TABLE obj_achievement       AUTO_INCREMENT = 1;
ALTER TABLE course_achievement    AUTO_INCREMENT = 1;
ALTER TABLE major_achievement     AUTO_INCREMENT = 1;

SET FOREIGN_KEY_CHECKS = 1;
```
