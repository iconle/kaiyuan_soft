## 需求

勘误工单须两级审批：教务管理员先审查（同意/拒绝），同意后转交管理员最终决定是否解锁。

## 流程

```
教师提交 → PENDING（待教务审核）
              ├── 教务「同意」→ APPROVED（待管理员解锁）
              │                    ├── 管理员「解锁」→ UNLOCKED（成绩单已解锁）
              │                    └── 管理员「拒绝」→ REJECTED
              └── 教务「拒绝」→ REJECTED

教师可随时查看工单状态，PENDING 时可撤销。
```

## 实现细节

### 后端

| 文件 | 变更 |
|------|------|
| `UnlockRequestService.java` | `approveRequest()` → 仅设 APPROVED 不执行解锁（限 ACADEMIC）；新增 `unlockApprovedRequest()` → 实际执行解锁（限 ADMIN）；`rejectRequest()` → 教务可拒 PENDING，管理员可拒 APPROVED |
| `AdminScoreController.java` | `/approve` → `@PreAuthorize("hasRole('ACADEMIC')")`；新增 `/unlock` → `@PreAuthorize("hasRole('ADMIN')")`；`/reject` → 传递 roleCode 校验权限边界 |

### 前端

| 文件 | 变更 |
|------|------|
| `ScoreUnlock.vue` | 根据角色显示不同按钮：教务→PENDING 显示「同意/拒绝」；管理员→APPROVED 显示「解锁/拒绝」；管理员→PENDING 显示「等待教务审核」标签 |
| `CourseCompute.vue` | 状态文案更新：PENDING=待教务审核、APPROVED=已同意等待管理员解锁、UNLOCKED=已解锁成绩可修改 |

### 权限矩阵

| 操作 | 教务(ACADEMIC) | 管理员(ADMIN) |
|------|:---:|:---:|
| 查看工单列表 | ✓ | ✓ |

| 拒绝 (PENDING/APPROVED→REJECTED) | PENDING可拒 | APPROVED可拒 |
