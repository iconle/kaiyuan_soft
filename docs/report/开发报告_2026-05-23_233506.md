## 问题

考核点通过 `assessment_objective` 表支持多目标绑定（N:M），但 `Level1Calculator` 仍使用 `AssessmentPoint.objectiveId`（单目标字段）筛选考核点→目标的映射关系。导致一个考核点绑定多个目标时，计算仅识别到第一个目标。

## 修复

### Level1Calculator 重构

- 移除 `AssessmentInfo` record（单 objectiveId 模式）
- 新增参数 `assessmentObjMap: Map<Long, List<Long>>`（assessmentId → 绑定目标列表）
- 筛选逻辑改为：检查 `assessmentObjMap[assessmentId]` 是否包含目标 ID

### CourseCalcService 更新

- 注入 `AssessmentObjectiveMapper`
- 加载 `assessment_objective` 表数据构建 `assessmentObjMap`
- 回退兼容：无 N:M 记录时使用 `AssessmentPoint.objectiveId` 兜底
- 调用 Level1Calculator 时传入 N:M 映射

### Level2 影响

Level2 计算依赖 Level1 输出的目标达成度 + 内部权重（`objective_indicator_weight`），不直接依赖考核点映射。Level1 修复后 Level2 自动正确。
