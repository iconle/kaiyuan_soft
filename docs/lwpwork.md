## 二、需求背景

### 1. 现状问题

在「支撑矩阵（宏观支撑矩阵配置）」页面中，专业负责人只能通过「添加课程支撑」对话框**逐个新增**课程对指标点的支撑关系（课程 + 支撑强度 + 指标点）。当一个专业的课程、指标点数量较多，或需要一次性配置多条支撑关系时，逐条手工添加非常繁琐、效率低。

### 2. 需求目标

- 新增「课程支撑导入」按钮，支持一次性批量导入课程支撑关系。
- 新增「下载模板」功能，提供标准填写模板。
- **导入模板的格式必须与专业负责人使用的导入模板保持一致**，否则系统应报错提示。
- **系统报错应明确指出问题所在以及用户需要修改的地方**。

> 本功能在设计上与已上线的「指标点批量导入」（分支 `lwp_99`）保持完全一致的模板风格与校验规则，复用同一套 POI 模板样式与逐行错误反馈机制。

## 三、功能设计

### 1. 模板格式

模板为一个 `.xlsx` 工作簿，包含两个 sheet：

**Sheet 1：课程支撑导入**（数据 sheet）

| 课程编号 | 课程名称   | 指标点编号 | 支撑强度(H/M/L) | 支撑权重 |
| -------- | ---------- | ---------- | --------------- | -------- |
| CS101    | 高等数学   | 3-1        | H               | 0.5      |
| CS102    | （可留空） | 3-1        | M               | 0.5      |
| CS101    | 高等数学   | 4-2        | L               | 0.3      |

- 表头（第一行）的**列名与顺序固定**，是导入时的强校验依据。
- 下载时会**预填当前专业下已存在的全部课程支撑关系**（课程编号、课程名称、指标点编号、支撑强度、支撑权重），方便用户在现有数据上增、删、改。
- 「课程编号」「课程名称」两列以浅黄底提示样式展示（参考列），其余列为数据列。
- 首行冻结，方便长列表滚动。

**Sheet 2：填写说明**

列出填写规则，并**动态列出当前专业可选的课程编号与指标点编号**，方便用户对照填写：

- 表头不可改、列顺序固定；
- 课程编号必填且必须为当前专业已存在课程；
- 课程名称仅作提示，可留空；
- 指标点编号必填且必须为当前专业已存在指标点（如 3-1）；
- 支撑强度只能填 H、M、L；
- 支撑权重为 0~1 之间的数字；
- 同一课程对同一指标点只能出现一次，同一指标点下所有课程支撑权重之和必须等于 1.00；
- 导入会整体替换当前专业的课程支撑关系，请基于下载的模板修改后再上传；
- 完全空白的行会被自动跳过。

### 2. 导入校验规则

| 校验项             | 规则                                                 | 失败提示示例                                                                            |
| ------------------ | ---------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 文件格式           | 必须为`.xlsx`                                      | 仅支持 .xlsx 格式文件，请点击「下载模板」获取正确模板                                   |
| 文件非空           | 不能上传空文件                                       | 上传文件为空，请选择模板文件                                                            |
| 表头一致性         | 首行必须与模板表头完全一致（列名 + 顺序）            | 模板格式不正确…期望表头：…；实际表头：…                                              |
| 课程前置           | 当前专业必须已存在课程                               | 当前专业尚未创建任何课程，请先新增课程后再导入课程支撑                                  |
| 课程编号           | 非空、必须在当前专业存在                             | 第3行：「课程编号 CS999」在当前专业不存在（有效课程编号：CS101、CS102…）               |
| 指标点前置         | 当前专业必须已存在指标点                             | 当前专业尚未创建任何毕业要求指标点，请先配置指标点后再导入课程支撑                      |
| 指标点编号         | 非空、必须在当前专业存在                             | 第5行：「指标点编号 9-1」在当前专业不存在（有效指标点编号：3-1、3-2…）                 |
| 支撑强度           | 非空、必须为 H/M/L（大小写不敏感）                   | 第7行：「支撑强度」必须为 H、M 或 L，实际为「高」                                       |
| 支撑权重           | 非空、必须为数字、范围 0~1                           | 第8行：「支撑权重」必须在 0~1 之间，实际为「1.5」                                       |
| 课程查重（文件内） | 同一课程 + 同一指标点不重复                          | 第9行：课程「CS101」对指标点「3-1」的支撑在本文件中重复出现                             |
| 权重合计           | 同一指标点下所有课程支撑权重之和 = 1.00（容差 0.01） | 指标点「3-1」的支撑权重之和为 0.60，不等于 1.00，请调整以下课程的支撑权重：CS101、CS102 |
| 空白行             | 完全空白的行自动跳过                                 | —                                                                                      |

### 3. 错误反馈策略

- **收集全部行级错误一次性返回**（而非遇错即停），用户可一次性对照修正，减少反复试错。
- 每条错误包含：**Excel 显示行号 + 字段名 + 实际值 + 正确取值范围**，明确告诉用户「哪一行、哪个字段、出了什么问题、应改成什么」。
- 权重合计类错误额外列出**涉及的课程编号清单**，便于定位调整。
- 错误以多行文本（`\n` 分隔）返回，前端在弹窗中换行展示。

### 4. 设计取舍

- **导入语义为「整体替换当前专业的课程支撑关系」**：校验全部通过后，先删除该专业全部课程的现有支撑记录，再插入文件中的数据。这与该页「提交生效」的全量保存模型一致，并支持通过删除模板中的行来移除某条支撑。模板已预填全部现有数据并提示「基于下载的模板修改后再上传」，避免误删。
- **权重合计约束**：宏观支撑矩阵要求每个指标点的总支撑权重 W_c = 1.0，因此导入时对文件中涉及的每个指标点做合计校验，保证替换后的矩阵依然满足归一化要求。
- 导入**按当前选中专业**进行，课程、指标点均匹配该专业**已存在**的数据，不创建新课程或新指标点。
- 涉及权限：沿用 `MacroMatrixController` 的类级 `@PreAuthorize("hasRole('DIRECTOR')")`，仅专业负责人可导入。

## 六、关键实现说明

### 1. 后端 MacroMatrixImportService

- `generateTemplate(majorId)`：使用 Apache POI（`XSSFWorkbook`）手动构建工作簿，复用与「指标点导入模板」「成绩录入模板」一致的样式（表头浅蓝、提示列浅黄、细边框、首行冻结）；预填当前专业已存在的课程支撑关系，并在「填写说明」中列出可选课程编号与指标点编号。
- `importMatrix(majorId, file)`：
  - 查询当前专业课程，构建 `课程编号 → courseId`、`courseId → 课程编号` 映射；为空直接报错。
  - 经毕业要求关联查询当前专业指标点，构建 `指标点编号 → indicatorId` 映射；为空直接报错。
  - 校验表头 → 逐行解析收集错误 → 校验每个指标点权重合计 = 1.0 → 无错则整体替换。
  - 全程 `@Transactional`，抛 `BizException` 由 `GlobalExceptionHandler` 统一转 JSON（HTTP 200 + `code=500`）。

### 2. 前端

- `MacroMatrix.vue` 头部新增「下载模板」「课程支撑导入」按钮，未选专业时禁用。
- 导入弹窗使用 `el-upload`（`:http-request` 自定义上传，`:before-upload` 校验 `.xlsx` 扩展名）。
- 下载走 blob，并对「后端业务异常以 HTTP 200 + JSON 返回」的情况做判别（检查 `blob.type` 是否含 `json`），避免把错误 JSON 当成 xlsx 下载。
- 导入失败时，`director.js` 中 `importMacroMatrix` 通过 `skipErrorMessage:true` 跳过全局 toast，由组件以 `ElMessageBox` 多行展示后端逐条错误（对内容做 HTML 转义后换行渲染，防注入）。
- 导入成功后自动 `loadData()` 刷新矩阵。

### 3. 与「指标点导入」的一致性

本功能的模板结构、表头强校验、逐行错误收集、`\n` 拼接一次性抛出、POI 样式、前端下载/上传交互均与已上线的「指标点批量导入」保持一致，确保专业负责人在不同导入入口获得统一体验；模板表头一旦被修改或上传了非标准文件，系统会明确提示「期望表头 vs 实际表头」并引导重新下载模板。

## 九、部署说明

### 后端

1. 切到 `lwp_103` 分支。
2. JDK 17 + Maven 构建：`mvn clean package -DskipTests`。
3. 用生成的 `obe-platform-1.0.0.jar` 替换部署目录中的旧 jar。
4. 重启后端服务。

### 前端

1. `cd frontend && npm run build`，产出 `dist/`。
2. 将 `dist/` 部署到 Nginx 静态目录（或按现有部署方式替换）。
3. 无需额外改 Nginx 配置（接口路径仍在 `/api/macro-matrix/**` 下）。

> 本地联调时注意：`frontend/vite.config.js` 中 `/api` 代理目标默认指向线上后端 `http://10.65.199.3:5173`，该后端无本分支新接口。要完整跑通需将代理目标改为本地后端（如 `http://localhost:8080`），或把后端改动部署到线上。
