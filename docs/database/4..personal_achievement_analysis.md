# 个人达成度数据存储分析报告

> **生成日期**: 2026-06-23  
> **分析对象**: "个人达成度"模块的数据来源与存储方式  
> **历史结论**: 数据**不存储在数据库中**，由后端接口每次访问时实时计算生成
> **更新说明**: issue #151 已新增 `personal_achievement` 表，后续课程目标级、课程指标点级和专业三级个人达成度会随计算流程落库。新增表结构见 `docs/database/5.personal_achievement_table.sql`。

---

## 一、数据库层面检查

### 1.1 现有达成度相关表

`sql/obe_platform.sql` 中仅包含以下 3 张达成度结果表，全部是**班级或以上级别**的聚合数据：

| 表名 | 级别 | 粒度 | 说明 |
|------|------|------|------|
| `obj_achievement` | 第一级 | 班级×课程目标 | 某个教学班级在某课程目标上的平均达成度 |
| `course_achievement` | 第二级 | 班级×指标点 | 某个教学班级在某指标点上的课程级达成度 |
| `major_achievement` | 第三级 | 专业×指标点×学期 | 某专业在某学期的专业级达成度 |

### 1.2 个人达成度表：不存在

对数据库中所有表结构进行检索，**不存在**以下任何命名的表：
- `personal_achievement`
- `student_achievement`
- `individual_achievement`
- 或其他以学生个体为粒度的达成度存储表

✅ **结论：数据库中不存储个人达成度数据。**

## 二、后端代码分析

### 2.1 API 接口

```
GET /api/classes/{classId}/personal-achievements          → 列表（概览）
GET /api/classes/{classId}/personal-achievements/{studentId} → 明细
GET /api/classes/{classId}/personal-achievements/excel       → 导出 Excel
```

三个接口全部是 **GET** 请求，无任何 POST/PUT/DELETE。权限：TEACHER / ACADEMIC / DIRECTOR。

### 2.2 核心逻辑：`PersonalAchievementService`

调用链路如下：

```
请求到达
    │
    ▼
loadContext(classId)          ← 只读查询，从数据库读取原始数据
    │
    ├── score_sheet           → 获取成绩单
    ├── course_outline        → 获取课程大纲
    ├── course_objective      → 获取课程目标列表
    ├── assessment_point      → 获取考核点及满分
    ├── assessment_question   → 获取题目及满分
    ├── assessment_objective  → 获取考核点→目标映射
    ├── question_objective    → 获取题目→目标映射
    ├── objective_indicator_weight → 获取目标→指标点权重
    ├── class_student         → 获取班级学生关联
    ├── student               → 获取学生基本信息
    ├── indicator             → 获取指标点编号
    └── student_score         → 获取学生成绩明细
    │
    ▼
calculateStudent()            ← 纯内存计算，无数据库写入
    │
    ├── Level1Calculator.calcObjectiveAchievement()
    │   └── 公式: C_ij = Σ实际得分 / Σ满分  (按学生i、目标j分别计算)
    │
    └── Level2Calculator.calcCourseAchievement()
        └── 公式: E_k = Σ(C_j × w_jk)  (目标达成度加权聚合到指标点)
    │
    ▼
返回 StudentAchievementDetail / StudentAchievementSummary
```

**关键特征**：
- `loadContext()` 方法仅执行 `selectOne` / `selectList` / `selectBatchIds` 等**只读查询**
- `calculateStudent()` 方法全程在内存中进行 BigDecimal 运算，**没有任何 INSERT/UPDATE/DELETE**
- 返回结果为 Java `record` 类型（`StudentAchievementSummary`、`StudentAchievementDetail`），非 JPA/MyBatis 实体，**无对应的数据库表**

### 2.3 计算公式

**第一级 — 目标级达成度（按学生个体）**:

```
C_ij = Σ(学生i在目标j相关考核点的实际得分) / Σ(对应满分)
```

- 优先使用题目级成绩（question_id != NULL），其次使用考核点级成绩
- 支持考核点→目标的多对多映射

**第二级 — 课程级达成度（按学生个体）**:

```
E_ik = Σ(C_ij × w_jk)    其中 Σ w_jk = 1.0
```

- 将学生 i 的各目标达成度 C_ij 代入课程级公式，得到该生在各指标点上的课程级达成度 E_ik
- 计算器复用 `Level2Calculator.calcCourseAchievement()`，与班级级课程达成度用**同一公式**，区别仅在于输入从班级均值 C̄_j 换成了单个学生的 C_ij
- 整体达成度取各指标点课程级达成度的算术平均

## 三、前端数据流

`PersonalAchievement.vue` 页面的数据流：

```
页面加载
    │
    ▼
GET /api/classes/{classId}/personal-achievements
    │
    ▼
后端实时计算 → 返回 JSON
    │
    ▼
前端展示表格（学号、姓名、各指标点达成度、整体达成度）
支持搜索过滤、Excel 导出
```

- **无缓存**：每次进入页面或刷新都重新请求
- **无持久化**：数据仅存在于 HTTP 响应的 JSON 中

## 四、达成度三级体系对比

| 级别 | 名称 | 粒度 | 存储方式 | 计算触发 |
|------|------|------|----------|----------|
| — | **个人达成度** | 学生个体 × 目标 + 指标点 | ❌ **不存储，实时计算** | 每次访问 API |
| 第一级 | 班级目标级达成度 | 班级均值 × 课程目标 | ✅ `obj_achievement` 表 | 成绩单锁定时 |
| 第二级 | 班级课程级达成度 | 班级均值 × 指标点 | ✅ `course_achievement` 表 | 第一级完成后 |
| 第三级 | 专业级达成度 | 专业 × 指标点 × 学期 | ✅ `major_achievement` 表 | 课程级完成后手动触发 |

> **注**：个人达成度实际是复用了上述三级的**前两级公式**（目标级 + 课程级），区别在于输入是单个学生的 C_ij 而非班级均值 C̄_j。因此个人达成度的计算结果实质上是**每个学生个体的目标级达成度和课程级达成度**，但计算结果不持久化，仅实时返回 API 响应。

## 五、结论

| 问题 | 答案 |
|------|------|
| 个人达成度数据存在数据库中吗？ | ❌ **不存在** |
| 数据如何获得？ | 后端接口实时计算，从 12 张原始数据表中读取并代入公式 |
| 是否需要清除上线前的数据？ | **不需要** — 没有持久化数据可清 |
| 上线后如何保证计算正确？ | 只需确保 `student_score` 等原始数据正确，计算逻辑不变 |
| 性能考量 | 每个学生独立计算，数据量大时可考虑加缓存，当前无持久化瓶颈 |
