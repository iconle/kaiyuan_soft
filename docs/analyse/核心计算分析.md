# 核心计算引擎架构及计算触发机制 — 深度分析

> 基于《软件需求规格说明书》第3章，以《数据结构》课程为实例，结合课程大纲与宏观支撑矩阵进行逐层推演。

---

## 1. 计算引擎总体架构

系统采用**"宏观矩阵 — 微观大纲"分离的双层权重设计**，数据按三个层级自下而上严格传导：

```
┌─────────────────────────────────────────────────────┐
│  第三级：专业级达成度（宏观总支撑权重 W）              │
│  G_k = Σ(E_k × W_c)                                │
├─────────────────────────────────────────────────────┤
│  第二级：课程级达成度（大纲内部贡献权重 w）            │
│  E_k = Σ(C̄_j × w_jk)                              │
├─────────────────────────────────────────────────────┤
│  第一级：课程目标级达成度（基于考核点得分）            │
│  C_ij = Σ(实际得分) / Σ(目标满分)                   │
└─────────────────────────────────────────────────────┘
```

每一级都有**严格的权重归一化约束**（Σ = 1.0），确保计算结果的数值一致性与可解释性。

## 2. 第一级：课程目标级达成度计算（3.1 节）

### 2.1 计算公式

针对学生 $i$ 和课程目标 $j$：

$$C_{ij} = \frac{\sum (\text{支撑目标 } j \text{ 的考核点实际得分})}{\sum (\text{支撑目标 } j \text{ 的考核点目标满分})}$$

班级课程目标 $j$ 的达成度 $\bar{C_j}$ 为全体学生 $C_{ij}$ 的算术平均值。

### 2.2 计算语义分析

该公式的核心含义是：**课程目标达成度 = 学生群体在相关考核点上的平均得分率**。

- 分子：学生 $i$ 在所有映射到目标 $j$ 的考核点上获得的实际分数之和
- 分母：这些考核点的满分（目标分值）之和
- 比值含义：该学生对目标 $j$ 所涉及知识/能力的掌握比例

### 2.3 实例推演：《数据结构》课程

#### 2.3.1 课程目标体系

根据《数据结构》课程大纲，共定义4个课程目标：

| 课程目标 | 维度 | 内容概要 |
|---------|------|---------|
| 目标1-1 | 知识 | 掌握4种数据结构概念和特征，能为实际问题选择合适数据结构 |
| 目标2-1 | 能力 | 分析复杂问题的数据结构和算法策略，比较算法复杂度 |
| 目标2-2 | 能力 | 建立数据模型，设计算法并编程实现及测试 |
| 目标3-1 | 价值 | 培养严谨逻辑思维和求真务实的科学精神 |

#### 2.3.2 考核点结构与目标映射

根据大纲表4-1的成绩构成，考核点体系如下：

| 考核/评价环节 | 分值占比 | 映射的课程目标 |
|-------------|---------|--------------|
| 平时成绩（在线作业、课堂测试） | 10% | 目标1-1 |
| 实验（代码、报告） | 20% | 目标2-2、目标3-1 |
| 期中测试 | 20% | 目标1-1、目标2-2 |
| 期末考试 | 50% | 目标1-1、目标2-1、目标2-2 |

#### 2.3.3 目标级达成度计算示例

假设班级有 $N$ 名学生，以**目标1-1**为例：

该目标被三个考核环节支撑：平时成绩、期中测试、期末考试。

对于学生 $i$：

$$C_{i,目标1\text{-}1} = \frac{\text{平时成绩得分} + \text{期中卷面得分} + \text{期末卷面中目标1-1相关题目的得分}}{\text{平时满分} + \text{期中满分} + \text{期末中目标1-1相关题目的满分}}$$

> **注意：** 期末考试同时支撑目标1-1、2-1、2-2，教师需要在系统中将期末试卷拆分为具体考核点（如"期末大题1""期末大题2"），并将每个考核点绑定至唯一的课程目标。

班级目标1-1达成度：

$$\bar{C}_{目标1\text{-}1} = \frac{1}{N} \sum_{i=1}^{N} C_{i,目标1\text{-}1}$$

同理可计算 $\bar{C}_{目标2\text{-}1}$、$\bar{C}_{目标2\text{-}2}$、$\bar{C}_{目标3\text{-}1}$。

## 3. 第二级：课程级达成度计算（3.2 节）

### 3.1 计算公式

$$E_{k} = \sum_{j} \left( \bar{C_j} \times w_{jk} \right)$$

**系统约束：** 对同一指标点 $k$，$\sum w_{jk} = 1.0$。

### 3.2 计算语义分析

课程级达成度的含义是：**该课程对某一毕业要求指标点的综合贡献度**，由各课程目标的达成度加权求和得到。权重 $w_{jk}$ 代表课程目标 $j$ 对指标点 $k$ 的贡献比例。

这一级实现了从"课程内部教学效果"到"毕业要求指标支撑"的语义转换。

### 3.3 实例推演：《数据结构》课程的内部贡献权重

根据大纲表1-1"课程目标与毕业要求指标点对应的矩阵关系"：

| 课程目标 | 毕业要求指标3-1 ($w$) | 毕业要求指标3-3 ($w$) | 毕业要求指标3-4 ($w$) |
|---------|:---:|:---:|:---:|
| 目标1-1 | **1.0** | — | — |
| 目标2-1 | — | **0.5** | — |
| 目标2-2 | — | **0.5** | — |
| 目标3-1 | — | — | **1.0** |
| **列合计** | **1.0** ✓ | **1.0** ✓ | **1.0** ✓ |

三个指标点各自的权重列合计均为 1.0，满足系统约束。

### 3.4 课程级达成度计算结果

假设第一级计算得出以下班级目标达成度值（示例数据）：

| 目标 | 达成度 $\bar{C_j}$ |
|------|:---:|
| 目标1-1 | 0.72 |
| 目标2-1 | 0.68 |
| 目标2-2 | 0.75 |
| 目标3-1 | 0.80 |

则课程级达成度计算如下：

**对指标点3-1（学科素养-专业知识）：**

$$E_{3\text{-}1} = \bar{C}_{目标1\text{-}1} \times 1.0 = 0.72 \times 1.0 = 0.72$$

**对指标点3-3（学科素养-工程实践）：**

$$E_{3\text{-}3} = \bar{C}_{目标2\text{-}1} \times 0.5 + \bar{C}_{目标2\text{-}2} \times 0.5 = 0.68 \times 0.5 + 0.75 \times 0.5 = 0.715$$

**对指标点3-4（学科素养-中学信息技术链接）：**

$$E_{3\text{-}4} = \bar{C}_{目标3\text{-}1} \times 1.0 = 0.80 \times 1.0 = 0.80$$

至此，《数据结构》课程产出了三个指标点维度的课程级达成度值 $(0.72,\ 0.715,\ 0.80)$，将作为第三级计算的输入。

## 4. 第三级：专业级达成度计算（3.3 节）

### 4.1 计算公式

$$G_{k} = \sum \left( E_{k} \times W_{c} \right)$$

**系统约束：** 对同一指标点 $k$，$\sum W_{c} = 1.0$。

### 4.2 计算语义分析

专业级达成度是**最终产出**，代表某一届学生在某项毕业要求指标点上的整体达成水平。它通过宏观支撑矩阵中各课程的权重，将所有相关课程的贡献加权汇总。

与第二级的区别：
- 第二级的 $w$ 是课程**内部**目标之间的贡献比例（微观），由主讲教师设定
- 第三级的 $W$ 是课程**之间**的支撑强度比例（宏观），由专业负责人设定

### 4.3 宏观支撑矩阵分析

根据"计算机科学与技术课程与毕业要求指标点支撑矩阵.xlsx"，专业共设8项毕业要求，分解为24个二级指标点（1-1 至 8-3）。

矩阵中的课程以 H（高支撑）、M（中等支撑）、L（低支撑）标记对指标点的支撑强度。系统要求专业负责人将这些定性标记转化为定量的总支撑权重 $W_c$，并确保每个指标点下的权重之和为 1.0。

以**指标点3-1**为例，从矩阵中提取支撑课程：

| 支撑课程 | 强度标记 | 建议权重方向 |
|---------|:---:|---------|
| 高等数学B | H | 较高权重 |
| 大学物理B | H | 较高权重 |
| 大学物理实验B | H | 较高权重 |
| 线性代数 | H | 较高权重 |
| 数据结构（本课程） | H | 较高权重 |
| 教育学 | M | 中等权重 |
| 其他标注H/M的课程 | ... | ... |

> **关键机制：** 定性标记（H/M/L）仅为参考，最终 $W_c$ 需由专业负责人手动设定并确保归一化。系统需提供实时校验，权重总和不为 1.0 时禁止提交。

### 4.4 专业级达成度计算示例

假设指标点3-3（工程实践能力）被以下课程支撑，且已设定权重：

| 课程 | 课程级达成度 $E_k$ | 总支撑权重 $W_c$ | 贡献值 $E_k \times W_c$ |
|-----|:---:|:---:|:---:|
| 数据结构 | 0.715 | 0.30 | 0.2145 |
| 高等数学B | 0.70 | 0.20 | 0.1400 |
| 大学物理B | 0.65 | 0.15 | 0.0975 |
| 学科教学理论与实践 | 0.78 | 0.35 | 0.2730 |
| **合计** | — | **1.00** | **$G_{3\text{-}3}$ = 0.7250** |

该专业在指标点3-3上的最终达成度为 **0.725**。

## 5. 计算触发机制分析（3.4 节）

### 5.1 两阶段触发模型

系统的计算链路被严格拆分为两个独立阶段，确保数据完整性与业务职责分离：

```
阶段一（教师级触发）                     阶段二（全局级触发）
┌──────────────────────┐              ┌──────────────────────┐
│ 触发者：课程主讲教师    │              │ 触发者：专业负责人/教务  │
│ 前置条件：成绩导入完成   │              │ 前置条件：所有课程已锁定  │
│                        │              │                        │
│  ① 计算目标级达成度     │    锁定      │  ③ 汇聚课程级达成度     │
│     C̄_j（3.1节）       │──────────▶ │     E_k（3.2节输出）   │
│                        │   各课程     │                        │
│  ② 计算课程级达成度     │   独立锁定   │  ④ 计算专业级达成度     │
│     E_k（3.2节）       │              │     G_k（3.3节）       │
│                        │              │                        │
│  结果：本课程数据锁定    │              │  结果：专业级数据持久化  │
└──────────────────────┘              └──────────────────────┘
```

### 5.2 阶段一：教师级触发

- **触发者：** 课程主讲教师
- **触发时机：** 完成单科成绩导入并确认无误后
- **计算范围：** 3.1（目标级）+ 3.2（课程级）
- **结果行为：** 计算结果持久化，成绩单状态变更为"已锁定"，教师丧失修改权限
- **独立性：** 每门课程的阶段一计算互不干扰，可并行执行

### 5.3 阶段二：全局级触发

- **触发者：** 专业负责人或教务管理员
- **触发时机：** 所有先决课程完成阶段一计算并锁定后
- **计算范围：** 3.3（专业级）
- **前置校验：** 系统提供宏观看板，展示所有支撑课程的计算状态（已锁定/未提交）
- **结果行为：** 专业级达成度持久化，供报表模块调用

### 5.4 触发机制的设计约束

| 约束项 | 说明 |
|-------|------|
| **锁定不可逆** | 成绩一旦锁定，主讲教师无法自行修改，需提交工单由教务管理员解锁 |
| **阶段依赖性** | 阶段二必须等待所有相关课程的阶段一完成后才能执行 |
| **事务隔离** | 多名教师同时上传/计算时，需保证事务隔离级别，防止幻读或死锁 |
| **数据可追溯** | 从最终的专业级达成度可逐层下钻至课程级→目标级→学生个人考核点得分 |

## 6. 数据溯源链路完整性分析

系统要求从顶层输出可一路回溯到底层数据。以指标点3-1为例，完整溯源路径如下：

```
专业级达成度 G_{3-1} = 0.72
  │
  ├─ 数据结构 E_{3-1} = 0.72, W = 0.30
  │   │
  │   └─ 目标1-1 C̄ = 0.72, w = 1.0
  │       │
  │       ├─ 平时成绩（在线作业、课堂测试）→ 目标1-1
  │       │   └─ 学生i得分: 85/100, 学生j得分: 78/100, ...
  │       │
  │       ├─ 期中测试 → 目标1-1 相关题目
  │       │   └─ 学生i得分: 18/20, 学生j得分: 16/20, ...
  │       │
  │       └─ 期末考试 → 目标1-1 相关题目
  │           └─ 学生i得分: 40/50, 学生j得分: 35/50, ...
  │
  ├─ 高等数学B E_{3-1} = 0.70, W = 0.25
  │   └─ ...
  │
  └─ 其他支撑课程 ...
```

这种"穿透式"溯源能力是认证专家审查时的核心诉求，也是模块D（报表生成）中"穿透式Excel数据台账"的数据基础。

## 7. 权重归一化约束的系统校验要点

### 7.1 第二级校验（微观权重 $w$）

- **校验维度：** 按指标点 $k$ 横向求和
- **校验时机：** 教师设定内部贡献权重时实时校验
- **约束：** 每个指标点 $k$ 下的 $\sum w_{jk} = 1.0$
- **校验方式：** 仅向教师透出本课程负责的指标点，按指标点列方向校验

**《数据结构》实例校验：**

- 指标点3-1：$w_{1\text{-}1 \to 3\text{-}1} = 1.0$ → Σ = 1.0 ✓
- 指标点3-3：$w_{2\text{-}1 \to 3\text{-}3} + w_{2\text{-}2 \to 3\text{-}3} = 0.5 + 0.5 = 1.0$ ✓
- 指标点3-4：$w_{3\text{-}1 \to 3\text{-}4} = 1.0$ → Σ = 1.0 ✓

### 7.2 第三级校验（宏观权重 $W$）

- **校验维度：** 按指标点 $k$ 纵向求和（跨课程）
- **校验时机：** 专业负责人设定总支撑权重时实时校验
- **约束：** 每个指标点 $k$ 下所有支撑课程的 $\sum W_c = 1.0$
- **校验方式：** 宏观矩阵二维网格界面，按列实时求和，不为1.0时标红并禁止提交

## 8. 计算引擎的边界条件与异常场景

| 场景 | 影响分析 | 系统应对策略 |
|-----|---------|------------|
| 教师未将考核点映射至目标 | 第一级公式分母为0 | 录入时强制要求每个考核点绑定唯一目标 |
| 某指标点无任何课程支撑 | 第三级无法计算 | 宏观矩阵配置时校验：每个指标点至少1门课程支撑 |
| 考核点满分设为0 | 除零错误 | 系统禁止满分值为0的考核点 |
| 学生成绩缺交（0分） | 达成度降低，属正常业务场景 | 无需特殊处理，0分计入统计 |
| 部分课程未完成阶段一 | 阶段二无法触发 | 宏观看板展示"未提交"状态，阻止全局计算 |
| 权重设定精度问题 | 浮点累加误差 | 使用高精度数值类型，校验时设置容差（如 0.999~1.001） |

---

## 9. 总结

核心计算引擎的本质是一个**三层加权聚合管道**：

1. **底层（考核点→目标）：** 纯算术比率，反映学生群体对特定教学目标的达成情况
2. **中层（目标→课程级指标点）：** 微观权重加权，将课程内部的多维教学效果投射到毕业要求维度
3. **顶层（课程→专业级指标点）：** 宏观权重加权，跨课程汇聚形成专业整体的达成度评价

两层权重（$w$ 和 $W$）均以 $\sum = 1.0$ 为不变约束，保证了计算结果的标准化与可比较性。两阶段触发机制则确保了数据流的有序性与一致性。
